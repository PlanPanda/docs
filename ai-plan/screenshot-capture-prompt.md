# Prompt: ให้ AI capture + crop + วาดลูกศร รูปคู่มือ 71 จุด (รันใน repo smart)

> วิธีใช้: เปิด ZCode ที่ repo `smart` (แอปจริง) แล้ววาง prompt ด้านล่างทั้งก้อน
> agent จะอ่านสเปคจาก `../docs/SCREENSHOTS.md` แล้วเขียนรูปลง `../docs/public/images/manual/` ให้เอง

---

## โจทย์

คู่มือ (repo `../docs`) มีจุดที่รอ screenshot 71 จุด ระบุไว้ครบใน `../docs/SCREENSHOTS.md` (คอลัมน์: ชื่อไฟล์ / ต้อง capture อะไร / เตรียมหน้าจอยังไง / หน้าที่ใช้)

ให้แก่ browser automation ไป capture ทีละจุด **crop ให้เห็นภาพรวมของงานนั้น** และ **วาดลูกศรชี้จุดสำคัญ** แล้วบันทึกเป็นไฟล์ `../docs/public/images/manual/<ชื่อไฟล์>.png` ให้ตรงชื่อเป๊ะ ๆ

## ขั้นเตรียม (ทำครั้งเดียว)

1. อ่าน `../docs/SCREENSHOTS.md` ทั้งไฟล์ แล้วเช็คว่ามีไฟล์ไหนใน `../docs/public/images/manual/` มีอยู่แล้ว — ข้าม slot นั้น
2. รันแอปในโหมด dev (ตรวจจาก package.json ว่า script ไหนรันทั้ง API + หน้าเว็บ) ให้พร้อมใช้งาน จด URL
3. **เตรียมบัญชีทดสอบ + ข้อมูล demo:** ใช้ seeder ของโปรเจกต์ หรือสร้างข้อมูลผ่าน API/DB โดยตรงใน dev ให้ครบพอสำหรับทุก slot (ลูกค้าทั้งผู้มุ่งหวังและลูกค้าหลายคน, กรมธรรม์บางส่วนมีสัญญาเพิ่มเติม/ตารางมูลค่าเวนคืน, กิจกรรมหลายขั้นตอน, นัดหมายหลายวัน, เพื่อน 1–2 คน, พอยต์/ประวัติเติมเงิน)
   - **ห้ามใช้บัญชีจริงหรือข้อมูลลูกค้าจริงเด็ดขาด** — ใช้ชื่อสมมุติแบบไทยธรรมชาติ
   - ถ้าต้องแก้/เพิ่มไฟล์ seed ชั่วคราว ให้ทำในไฟล์แยกและรายงานไว้ตอนจบ
4. เข้าสู่ระบบด้วย browser automation แล้วตั้งค่า: viewport **1440×900, deviceScaleFactor 2** (ภาพคม), โหมด **light** ของแอป, ภาษาไทย

## ขั้น capture (ทีละ slot ตามตาราง)

สำหรับ slot แต่ละตัว:

1. ไปที่หน้าตามคอลัมน์ "หน้าที่ใช้" แล้ว**เตรียมสถานะหน้าจอตามคอลัมน์ "เตรียมหน้าจอยังไง"** ให้ครบ (เปิดแผง/พิมพ์ค้นหา/เลือกแท็บ ฯลฯ)
2. **เลือกจุดที่ลูกศรจะชี้:** จากคอลัมน์ "ต้อง capture อะไร" + หน้าจอจริง ให้เลือก control ที่เป็นหัวใจของ slot นั้น (เช่น ปุ่มเพิ่มผู้มุ่งหวัง, ช่องค้นหา, การ์ดยืนยัน) มีได้ 1–3 จุด
3. **วาดลูกศรแบบผูกกับ DOM:** หา element จริงด้วย locator → อ่าน bounding box → ฉีด SVG overlay ทับหน้าเว็บ:
   - ลูกศรสีดำ เส้นหนา 3–4px มีหัวลูกศร มีขอบขาวบาง ๆ ให้เด่นบนพื้นใดก็ได้ ชี้จากพื้นที่ว่างเข้าหา element
   - ถ้ามีมากกว่า 1 จุด ใส่ป้ายวงกลมเลข ① ② ขาว-ดำกำกับ
   - overlay ต้องไม่ทับข้อความสำคัญของ UI ที่ต้องการโชว์
4. **ถ่ายภาพ viewport** (full viewport ไม่ต้อง full page)
5. **crop:** ตัดขอบว่าง/ส่วนไม่เกี่ยวออกให้เห็นภาพรวมของงานนั้นชัด ๆ เว้นขอบรอบ ๆ อย่างน้อย 40px และต้องไม่ตัดลูกศร/ป้ายขาด — ใช้พิกัดจาก bounding box ของ overlay ช่วยกำหนดกรอบ (crop ด้วย sharp หรือ library ที่มีในโปรเจกต์)
6. บันทึกเป็น `../docs/public/images/manual/<ชื่อไฟล์>.png` (สร้างโฟลเดอร์หมวดถ้ายังไม่มี)
7. **ตรวจรูปทุกใบด้วยตัวเอง:** เปิดดูรูป — ลูกศรต้องชี้ตรงจุด, ข้อความ UI อ่านได้, ไม่มีสิ่งแปลกปลอม (cursor แปลก, แถบ dev, notification พลอย) ถ้าไม่ผ่าน เตรียมหน้าจอใหม่แล้วถ่ายซ้ำ

## กติกา

- ทำตามลำดับ slot ไปเรื่อย ๆ จนครบทุกจุดที่ทำได้
- slot ไหนทำไม่ได้จริง ๆ (เช่น ต้องการ error state ที่ trigger ยาก, ข้อมูลที่ seed ไม่ได้, ต้องรอ AI ตอบจริง) ให้**ข้ามและจดเหตุผล** อย่าฝืนถ่ายรูปที่ผิดจากความจริงของระบบ
- ห้ามแก้โค้ดแอป / ห้ามแก้เนื้อหา docs — แตะเฉพาะไฟล์รูปใน `../docs/public/images/manual/` + seed ชั่วคราวถ้าจำเป็น
- ถ้าหน้าเว็บใช้ข้อมูล AI จริงและเสียพอยต์ ให้ตั้งค่า mock/เลี่ยงการเรียกจริง หรือข้าม slot นั้นแล้วรายงาน

## ส่งมอบ

รายงานสรุป: ✅ จำนวน slot ที่ capture สำเร็จ, ❌ slot ที่ข้ามพร้อมเหตุผล, ไฟล์ seed ชั่วคราวที่เกิดขึ้น, และบอกให้ผู้ใช้ "รัน `pnpm build` ใน ../docs แล้วเปิดดู placeholder ที่เหลือ" เป็นขั้นตรวจสุดท้าย
