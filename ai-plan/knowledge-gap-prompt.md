## โจทย์

ใน `knowledge-for-manual/` ยังขาดเนื้อหา 7 หน้าที่คู่มือ (docs repo) มีอยู่ ให้สร้างไฟล์ knowledge เหล่านี้จากพฤติกรรมจริงของโค้ดใน repo นี้:

1. `knowledge-for-manual/start/quick-start.md` — เริ่มใช้งานจริงใน 10 นาที (สมัคร → เพิ่มผู้มุ่งหวังคนแรก → จดกิจกรรมแรก → ดูหน้ารายงาน) ไล่ทีละขั้นจาก onboarding จริงในโค้ด
2. `knowledge-for-manual/customer/workflow-after-call.md` — Workflow หลังคุยลูกค้า 2 นาที: จดกิจกรรม → ผลลัพธ์ → นัดครั้งต่อไป → สร้างนัดในปฏิทิน อ้างอิงหน้าจอจริง
3. `knowledge-for-manual/customer/pdpa.md` — PDPA & ความเป็นส่วนตัวลูกค้า: ฟิลด์ consent ของลูกค้า, หลักการที่ระบบเก็บอะไร/ไม่เก็บอะไร, สิทธิ์ลบข้อมูล, การที่เพื่อนในทีมไม่เห็นข้อมูลลูกค้าของเรา
4. `knowledge-for-manual/team/metrics-and-privacy.md` — ตัวเลขทีม & ความเป็นส่วนตัว: เพื่อนเห็นอะไรได้/ไม่ได้ (กิจกรรมรายสัปดาห์, ยอดขายเทียบเป้าหมาย) และสิ่งที่ถูกซ่อนตลอด (รายชื่อลูกค้า, โน้ต, กรมธรรม์)
5. `knowledge-for-manual/help/faq.md` — คำถามที่พบบ่อย รวบรวมจาก error message จริงในโค้ด + พฤติกรรมระบบ (เช่น ลืมรหัสผ่าน, ยอดเงินไม่พอ/โหมดดูอย่างเดียว, แนบไฟล์ไม่ผ่าน, แชท AI error แต่ละแบบ, ลบสนทนา, เปลี่ยนแพ็คเกจ)
6. `knowledge-for-manual/help/5-steps.md` — กิจกรรม 5 ขั้นตอนคืออะไร: อธิบาย 5 ขั้นของ Sale Funnel (หาลูกค้าใหม่ สร้างความสัมพันธ์ เสนอขาย ปิดการขาย ดูแลหลังขาย) จาก definition จริงในโค้ด + ตัวอย่างการใช้
7. `knowledge-for-manual/settings/ai-connections.md` — (มี stub อยู่แล้ว) ขยายให้สมบูรณ์: หน้าเชื่อมต่อแอป AI อื่นด้วย API Key และ OAuth, ระดับสิทธิ์ read/write/delete, ค่าเริ่มต้นที่ปิด write/delete, วิธีเพิกถอน

## กติกาการเขียน (ตามที่ knowledge-for-manual ทุกไฟล์ใช้)

- อ่าน `GLOSSARY.md` และ `knowledge-for-manual/index.md` (หัวข้อ rewrite rules) ก่อนเขียน ใช้ศัพท์ตรงตาม GLOSSARY
- อ่านไฟล์ตัวอย่าง 1–2 ไฟล์ เช่น `knowledge-for-manual/ai/assistant.md`, `knowledge-for-manual/customer/customer-list.md` เพื่อจับน้ำเสียง: ภาษาไทยแบบพูดคุย ใช้ "คุณ/เรา" ปิดท้ายด้วยกำลังใจเบา ๆ
- เขียนจาก **มุมผู้ใช้** เท่านั้น — ห้ามเล่าชื่อไฟล์/ฟังก์ชัน/API ในโค้ด ให้ไล่ตามหน้าจอและปุ่มจริง
- ตรวจพฤติกรรมจริงจากโค้ด (routes, components, validation, error message) ทุกข้อที่เขียน ห้ามเดา ถ้าหาจริงแล้วไม่มีฟีเจอร์นั้น ไม่ต้องเขียน
- ทุกจุดที่ควรมีรูปให้ใส่ marker รูปแบบ: `<!-- IMAGE: screenshot ...คำอธิบายกรอบที่ต้องเห็น... -->` (1–4 จุดต่อไฟล์)
- ความยาวโดยประมาณไฟล์ละ 40–80 บรรทัด เท่าไฟล์ที่มีอยู่
- อัปเดต TOC ใน `knowledge-for-manual/index.md` ให้ชี้ไฟล์ใหม่ด้วย

## นิยาม "เสร็จ"

- ไฟล์ใหม่ 7 ไฟล์ครบ + index.md อัปเดต + ไม่มีข้อความที่ขัดกับ GLOSSARY.md
